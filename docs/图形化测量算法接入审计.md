# 图形化测量算法接入审计

审计日期：2026-09-24

本次只读核对图形化试测、旧二次开发记录、旧`program_N`执行程序及已有验收记录。结论用于确定生成映射和硬件接入重点，不重复已经完成的实图稳定性测试。

## 结论

| 测量类型 | 代码审计结论 | 后续重点 |
|---|---|---|
| 角度 | 图形化入口已实现双ROI与单ROI相邻边，包含候选选择、方向/补角语义、异常与退化线拒绝；已有大量离线验收 | 生成时保存ROI、检测参数、角度模式和候选语义；不再安排常规重复试测 |
| 孔径 | 已按旧程序“上下边拟合后计算四组跨边距离并取最大值”的计算方式接入，并使用测孔标定 | 生成时保存ROI、均布个数、测孔标定和相机/轴点位；精度只随正式标定与样件复核 |
| 长度 | 单图模板定位与双边拟合、跨图端点拟合及轴5补偿公式均已接入；已有重复性和保存恢复验收 | 生成时保存模板、参考位姿、ROI、远心标定；跨图模式必须带两端轴5编码器点位 |
| 圆弧半径 | 当前适配层与旧函数采用同一核心HALCON圆拟合：Canny边缘、轮廓分段/筛选/合并、`FitCircleContourXld(..., "algebraic", -1, 0, 0, 3, 2)`；当前仅输出像素半径 | 生产映射补上远心标定和毫米结果，保存ROI及检测参数；不再重复基础识别测试 |
| 直径 | 原程序将轴5移动到记录点位，读取光幕OUT1并调用`diameter_compensation`；通常测量两次后取平均值 | 图形化生成器输出轴5点位、测量次数、公差；执行端直接复用光幕读取和补偿，不建立图像算法 |
| 圆柱度 | 原程序在轴5三个截面分别旋转轴7一周并连续读取补偿后直径，把三截面样本合并排序，以直径变化的一半输出圆柱度 | 建立公共执行适配层并补齐采样数量、超时、停止和非有限值校验；真实结果必须硬件验证 |
| 圆跳动 | 原程序在三个轴5截面旋转轴7采集OUT5，将直径/2作为半径、上下边位置差/2作为中心偏移，余弦拟合截面圆心，再按基准轴或顶尖模式计算三个截面跳动并取代表值 | 这是当前最高风险项：先修正生成模板和输入模型，再接运动采样；必须进行硬件安全与重复性验收 |

## 已确认的接口映射

- 直径输入：轴5目标pulse、测量次数、公称值及上下偏差。原执行函数见`program_10.cpp`的`lsSensorMeasure_diameter`；测量值来自光幕OUT1并经过`diameter_compensation`。
- 圆柱度输入：轴5下侧/中间/上侧三个pulse、采样间隔、公称值及上限。原执行函数见`lsSensorMeasure_cylindricity`，转台轴为轴7，一周为`360 * 500` pulse。
- 圆跳动输入：每个待测轴段的三个轴5 pulse、两个基准轴段或顶尖计算模式、采样间隔、公称/上限。执行顺序为采样、中心余弦拟合、基准轴拟合、三个截面跳动计算和结果汇总。
- 图形化前端现有`lowerAxialOffsetPulse`、`upperAxialOffsetPulse`和两项基准文本只能表达配置。生成时必须把基准文本解析为实际圆跳动记录索引，不能把文本直接交给执行函数。

## 接入前必须处理的问题

1. 审计发现`sdk_assist.cpp`曾把上下偏移写入相反变量，`AxisMeasurement.cpp`又按变量名计算上下点位，旧二次开发路径因此存在对调风险。本轮已改为上侧输入写入上侧变量、下侧输入写入下侧变量；图形化公共适配层另以独立参数计算三截面并检查整数范围。
2. 参考生成代码`program_参考.cpp:3185-3194`声明`referencePoint[6][3]`合理，但第二基准读取`roundoutDataPtr[5]`；同一模板的`roundoutDataPtr`长度为5且采集循环只覆盖0至4，存在越界示例。生成器必须按实际记录数量和已解析的两个基准索引生成，不能照抄固定5。
3. 圆柱度在`program_10.cpp:182-185`未校验样本数量便读取`diameter[dataSize-15]`；圆跳动在`roundoutCalculate`中读取`dataLength-13`和索引12，也没有最小样本、非有限值及采样完整性检查。采样不足会越界或产生无效结果。
4. `axisLoaction`用`directionVector[2]`作除数，没有退化基准轴保护。两个基准无效、重合或拟合失败时必须停止计算并报告错误。
5. 旧运动等待循环缺少统一超时、急停/取消传播和传感器失效判定。公共适配层必须使用现有安全停止机制，不能原样复制阻塞循环。
6. 部分旧程序按固定序号写死基准、数组长度和结果选择，并且存在同一临时结果向量跨分支复用的代码。生成器需要从记录关系生成明确索引，并在每项计算前清空局部数据。

## 收口边界

角度、孔径、长度和圆弧半径的算法代码审计到此收口。后续只做生成数据映射、标定传递和最终自动程序编译检查；除非出现回归或新图像类型，不再安排成套重复试测。

直径的算法本体是光幕读取、补偿和多次平均，重点是执行适配与真实硬件验证。公共适配层已提供直径平均、圆柱度旧语义计算、圆跳动距离与三截面代表值、基准轴投影、三截面点位以及运动超时/取消/故障主动停止策略。圆柱度和圆跳动仍需把真实光幕、轴5、轴7及余弦/轴线拟合后端接入该层，再进行硬件验收。无硬件阶段只能确认映射、计算防护和模拟数据行为。
