# AxisMeasurement 二次开发程序生成与集成流程

更新日期：2026-08-21

## 1. 使用范围

本流程用于在二次开发界面记录测量点位和特征，生成新的 `program_N.h/.cpp`，将其加入 Visual Studio 工程，并在回传旧电脑前完成验证。

## 2. 固定环境

- Visual Studio 2019，平台工具集 v142。
- Qt 5.14.2：`msvc2017_64`。
- 构建配置：`Release | x64`。
- Windows显示缩放：当前界面按100%验证。
- 主程序运行目录：`x64\Release`。

## 3. 生成前检查

1. 启动并登录软件。
2. 进入二次开发界面。
3. 填写零件编号、工序编号、点位和特征数据。
4. 未连接运动控制卡时，不应调用硬件位置读取；测试数据中的轴坐标不能用于正式测量。
5. 点击“输出表单”，确认 `SDKpostion` 下生成对应的 `.xlsx`。

## 4. 生成程序

1. “输出表单”会打开：
   `x64\Release\SDKprogram\program0107.xlsm`
2. 启用宏。
3. 输入未占用的程序索引号 `N`；点击取消或输入非正数时，宏安全退出。
4. 宏读取：
   `x64\Release\SDKpostion\*.xlsx`
5. 宏生成：
   - `x64\Release\SDKprogram\program_N_generated.xlsm`
   - `x64\Release\SDKprogram\generated\program_N.h`
   - `x64\Release\SDKprogram\generated\program_N.cpp`
6. `.h/.cpp` 使用带BOM的UTF-8编码。

## 5. 生成结果检查

生成后必须确认：

- `.h` 和 `.cpp` 中的类名都是 `program_N`。
- CPP包含 `#include "program_N.h"`。
- 不包含 `program_45`、`program_15` 或 `temporary_sun`。
- 报告路径使用：
  `runtimePath("measureData/Report/...")`。
- HALCON模型使用相对目录：
  `./programParmeter/...`。
- 中文没有乱码。

## 6. 加入工程

先备份：

- `AxisMeasurement.vcxproj`
- `AxisMeasurement.vcxproj.filters`
- `myCode\head\AxisMeasurement.h`
- `myCode\sourceCode\AxisMeasurement.cpp`

然后：

1. 复制 `program_N.h` 到 `myCode\head`。
2. 复制 `program_N.cpp` 到 `myCode\sourceCode`。
3. 在 `AxisMeasurement.vcxproj` 中将头文件注册为 `QtMoc`。
4. 在 `AxisMeasurement.vcxproj` 中将CPP注册为 `ClCompile`。
5. 在 `AxisMeasurement.h` 中增加头文件引用、程序对象指针和零件编号变量。
6. 在 `AxisMeasurement.cpp` 中创建程序对象并连接信号。
7. 在四个分派位置增加对应 `case N`：
   - 显示零件编号；
   - 启动自动测量；
   - 紧急停止；
   - 确认后继续。
8. 更新 `AxisMeasurement.ui` 中程序下拉框的显示文字。

## 7. 编译与离线回归

1. 重新加载Visual Studio项目。
2. 执行 `Release | x64` 全部重新生成。
3. 检查新程序的C/C++、Qt MOC和LNK诊断。
4. 启动、登录、进入主窗口并正常关闭。
5. 无硬件时不得运行真实自动测量。

## 8. 回传旧电脑

回传前至少保留：

- `.sln`、`.vcxproj`、`.vcxproj.filters`；
- `myCode`；
- `inc`、`lib`；
- `config`、`programParmeter`、`SDKpostion`；
- `x64\Release` 中完整运行环境；
- 修改后的 `program0107.xlsm` 和对应阶段备份。

旧电脑必须重新生成源码，不能只替换EXE。重新生成后依次验证：

1. Qt、OpenCV、HALCON及设备SDK环境正常。
2. 程序启动和登录正常。
3. 所有设备能够打开。
4. 运动控制卡成功打开后 `openControllerFlag == true`。
5. 手动移动、点位记录和自动测量按现场安全规程逐项验证。

## 9. 已记录但不阻塞当前流程的问题

### SDK-OFFLINE-001

- 现象：未连接硬件时，直径点位记录曾偶发闪退。
- 原因判断：点位入口直接调用运动控制卡，缺少连接状态保护。
- 已完成：`openControllerFlag` 默认值改为 `false`。
- 待改进：所有点位记录入口统一检查控制卡和相机连接状态。

### BUG-REG-001

- 现象：程序46至50的选择分支均显示 `partNumber_25`。
- 原因：复制分支后未修改变量编号。
- 改进：分别改为 `partNumber_46` 至 `partNumber_50`。

### XLSM-FORMULA-001

- 现象：生成器部分未参与当前生成的辅助工作表存在 `#REF!/#NAME?`。
- 当前影响：本次生成的 `together/togethercpp` 已验证正确，不阻塞主流程。
- 后续：按实际启用的测量特征逐表修复和回归。
